# Cadrage Fonctionnel : Multijoueur en ligne

## 1. Contexte & Problème
- **Cible :** Deux joueurs souhaitant jouer à distance (pas dans la même pièce)
- **Problème résolu :** Impossible de jouer ensemble sans être physiquement présents
- **Bénéfice attendu :** Lancer une partie en temps réel avec un ami via un simple code de partie

## 2. Périmètre
- **Inclus (MVP) :**
  - Écran d'accueil avec deux boutons : "Créer une partie" et "Rejoindre une partie"
  - Génération d'un code de partie court et lisible (ex : `VAULT-42`)
  - Saisie du code pour rejoindre une partie existante
  - Synchronisation des coups en temps réel entre les deux joueurs
  - Détection de déconnexion → annulation automatique de la partie + message d'information
  - Serveur hébergé gratuitement (tier free)
- **Exclu (Hors périmètre) :**
  - Reconnexion après fermeture de l'app
  - Système de lobby / liste de parties publiques
  - Authentification / comptes utilisateurs
  - Chat entre joueurs
  - Historique des parties en ligne
  - Plus de 2 joueurs simultanés par partie

## 3. Parcours Utilisateur & Récits (User Stories)

### Créer une partie
- En tant que Joueur X, je veux créer une partie et obtenir un code, afin de l'envoyer à mon ami pour qu'il me rejoigne.

**Scénario nominal :**
1. Joueur X ouvre l'app
2. Il appuie sur "Créer une partie"
3. L'app affiche un code de partie (ex : `VAULT-42`) et un message "En attente de l'adversaire…"
4. Joueur X copie/partage le code via Signal, WhatsApp, SMS…
5. Dès que Joueur O rejoint, la partie démarre automatiquement — Joueur X joue en premier (X)

### Rejoindre une partie
- En tant que Joueur O, je veux saisir un code reçu de mon ami, afin de rejoindre sa partie en cours.

**Scénario nominal :**
1. Joueur O ouvre l'app
2. Il appuie sur "Rejoindre une partie"
3. Il saisit le code (ex : `VAULT-42`) et confirme
4. La partie démarre — Joueur O joue en second (O)

### Jouer en temps réel
- En tant que joueur actif, je veux voir les coups de mon adversaire apparaître instantanément, afin de jouer sans délai.

**Scénario nominal :**
1. Joueur X joue un coup → la grille se met à jour sur les deux téléphones
2. C'est au tour de Joueur O → il joue → la grille se met à jour
3. Si 3 cases alignées → écran de victoire habituel (Vault Boy + "Joueur X a gagné !")
4. Si grille pleine sans vainqueur → message match nul
5. Bouton "Rejouer" → relance une nouvelle partie dans la même room

### Déconnexion
- En tant que joueur en cours de partie, je veux être informé si mon adversaire quitte, afin de ne pas rester bloqué à attendre.

**Scénario :**
1. L'un des joueurs ferme l'app
2. L'autre joueur voit un message : "Votre adversaire a quitté la partie."
3. La partie est annulée — bouton "Retour à l'accueil" proposé

## 4. Règles Métier & États Limites

| Situation | Comportement attendu |
|-----------|---------------------|
| Code de partie inexistant | Message d'erreur : "Code invalide ou partie introuvable." |
| Partie déjà complète (2 joueurs) | Message : "Cette partie est déjà en cours." |
| Déconnexion d'un joueur | Partie annulée, message affiché à l'autre joueur |
| Reconnexion après fermeture | Non supporté — retour à l'accueil obligatoire |
| Joueur X et O dans la même room | Joueur X joue toujours en premier |

## 5. Critères d'Acceptation (Format Gherkin)

```gherkin
Étant donné que Joueur X appuie sur "Créer une partie",
Quand la room est créée,
Alors un code lisible (format XXXX-00) est affiché et la partie attend Joueur O.

Étant donné que Joueur O saisit un code valide,
Quand il confirme,
Alors la partie démarre et chaque joueur voit la grille vide.

Étant donné que c'est le tour de Joueur X,
Quand il appuie sur une case vide,
Alors la case affiche "X" sur les deux téléphones en moins de 2 secondes.

Quand le coup est joué,

Quand la déconnexion est détectée,
Alors l'autre joueur voit "Votre adversaire a quitté la partie." et peut retourner à l'accueil.

Étant donné que Joueur O saisit un code inexistant,
Quand il confirme,
Alors un message d'erreur s'affiche : "Code invalide ou partie introuvable."
